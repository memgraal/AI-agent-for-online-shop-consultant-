# Статус AI-части по ТЗ SSS

Дата сверки: 24 октября 2026 года.

Сверка ограничена AI-сервисом, AI API и связанным с ним FAQ Workbench по
[техническому заданию](../SSS%20ТЕХНИЧЕСКОЕ%20ЗАДАНИЕ.docx). Разработка интернет-магазина,
его CMS, корзины и внешних систем в этот список задач не входит. Источники из них
упоминаются только как будущие поставщики данных для AI-инструментов.

## Краткий вывод

Уже есть FastAPI/LangGraph-основа, пользовательский и административный агенты,
WebSocket/SSE-чат, настройки провайдеров, базовая защита/логирование и API анализа FAQ.
Ряд tool-контрактов пока возвращает заглушки. Основной AI-сервис не подключён к БД;
история и прототип базы знаний хранятся в памяти процесса. FAQ Workbench — отдельный
сервис со своей PostgreSQL-схемой и миграциями, но подключение к рабочей БД и полный
интеграционный прогон ещё нужны.

## Что уже есть

| AI-возможность из ТЗ | Реализация |
| --- | --- |
| Отдельный API AI-сервиса | FastAPI и асинхронные графы LangGraph для клиентского чата, админ-помощника и FAQ-анализа |
| Диалог с пользователем | WebSocket с обычным/потоковым режимами; HTTP и SSE оставлены для совместимости |
| Быстрый и подробный режим | `quick`/`detailed`, отдельные лимиты генерации и ограничение контекста |
| Разделение клиентских и админских возможностей | Раздельные графы/инструменты; admin API-key и проверка Origin |
| Несколько провайдеров моделей | Настройка OpenAI, Yandex AI Studio и OpenAI-compatible endpoint |
| Базовая защита персональных данных | Маскирование распространённых email/телефонов/длинных чисел перед вызовом модели; структурные логи с allowlist полей |
| Сбор вводных для подбора | `create_installation_brief` формирует предварительное ТЗ и перечисляет незаполненные поля; сам товар не подбирает |
| Прототип поиска по документам | Админ API принимает текст/TXT/MD/PDF/DOCX с метаданными; keyword-поиск отдаёт фрагменты с цитируемыми полями источника |
| Группировка FAQ | JEv назначает категории вопросам; основная модель группирует вопросы внутри категорий и пишет текстовые поля FAQ; API валидирует индексы и сохраняет все источники |
| FAQ Workbench | Отдельные API, PostgreSQL-модели/миграции, маскирование, идемпотентный сбор, пороговый запуск, embeddings, черновики и публикация |

## Что работает только частично или пока является заглушкой

| AI-сценарий | Текущее состояние | Ограничение |
| --- | --- | --- |
| Подбор оборудования | Есть prompt и tool-контракт каталога | Репозиторий каталога — заглушка; фактические товары, SKU и комплекты не выдаются |
| Сравнение | Есть tool-контракт и правило оформлять сравнение Markdown-таблицей | Нет карточек и характеристик; нельзя подтвердить реальные значения |
| Ответы по инструкциям | Есть загрузка текста/TXT/MD/PDF/DOCX и поиск ключевых слов | Индекс живёт в памяти; нет долговремого/векторного поиска и контроля точности цитат |
| Корзина, скидки, реквизиты | Есть API расчёта по переданным ценам и форматы проверки ИНН/ОГРН/КПП | Это не авторитетный расчёт магазина или проверка существования компании; данные не сохраняются |
| Передача оператору | `call_operator` помещает обезличенную заявку в локальную очередь, доступную администратору | CRM/оператор не подключены; очередь в памяти не подтверждает фактическую доставку оператору |
| AI-функции админки | SEO-черновик и классификация через JEv, нормализация переданных атрибутов и кандидаты-дубли | Нет CMS/каталога и аналитики; публикация и слияние записей не выполняются |
| История чата | Серверные сессии по `conversation_id`, TTL и контекстный лимит | Хранение in-memory: сбрасывается при перезапуске и не разделяется между процессами |
| Управление FAQ | Workbench хранит кандидаты и умеет публиковать их через API | Нужны реальное подключение своей PostgreSQL, настройка запуска batch-пересчёта и интеграционный прогон |
| Управление AI-контентом | API тональности, отключаемых тем, проверенных FAQ и версий настроек; PostgreSQL-хранилище и история изменений | UI админки ещё нет; секреты и инфраструктурная конфигурация остаются в env/secret manager |

## Задачи, которые можно делать до подключения БД

- [x] **SEO-черновики и классификация товара.** Отдельные API возвращают проверенные
  Pydantic-объекты; JEv классифицирует, основная модель готовит SEO-поля.
- [x] **Нормализация атрибутов на переданных строках.** Возвращаются исходное и
  предложенное значения, объяснение и уверенность; исходные данные не изменяются.
- [x] **Поиск потенциальных дублей в переданных карточках.** Возвращаются пары и
  основания для ручной проверки; автоматического слияния нет.
- [x] **Приём документов без БД.** Поддержаны текст/TXT/MD/PDF/DOCX с ограничением размера,
  проверкой типа и сохранением метаданных в памяти процесса.
- [x] **Регрессионные сценарии.** Контракты, пустые источники, PII, ошибки и поведение
  инструментов проверяются без платных вызовов моделей.
- [x] **Локальные прототипы контент-контролей, передачи оператору, расчёта заказа и
  проверки формата реквизитов.** Все входы/выходы валидируются; внешней доставки/проверки нет.
- [x] **Ограничения ресурсов API.** Ограничены LLM concurrency/queue wait, число чатов,
  документов, чанков, объём индекса, размер/PDF-страницы и rate limit обоих сервисов.
  За reverse proxy нужны общие rate/concurrency лимиты для нескольких workers.
- [ ] **Проверить каждого провайдера на реальных API-вызовах.** Tool calling,
  structured output для FAQ, стриминг, таймауты, отмена и ошибки; текущая конфигурация
  адаптера сама по себе это не доказывает.
- [ ] **Проверить WebSocket-клиентский поток в браузере.** Reconnect, несколько ходов,
  ошибки провайдера, долгие ответы и фактическую передачу разрешённого Origin.
- [ ] **Замерить качество, стоимость и задержку.** Критерий ТЗ — ответ за 5–7 секунд;
  его ещё нужно подтвердить на тестовом корпусе и целевых провайдерах.
- [ ] **Подготовить AI-эксплуатацию.** Агрегированные метрики,
  общие rate-limit на периметре, хранение секретов, резервное копирование AI-конфигурации,
  логов и хранилища знаний после его выбора.

## Задачи, ожидающие БД или доступ к источникам данных

### P0 — данные и персистентность AI

- [ ] **Зафиксировать контракт каталога для AI.** Нужны формат товара, атрибутов, SKU,
  цены, наличия, совместимости и ссылки на документ. Сам каталог/CMS в задачу AI не входит.
- [ ] **Подключить AI CatalogRepository к тестовому источнику.** Реализовать поиск,
  фильтры, подбор и сравнение; проверить, что модель использует только возвращённые
  поля и не придумывает цены/характеристики.
- [ ] **Подключить постоянное хранилище истории.** Схема диалогов, привязка к
  пользователю/сессии, контроль доступа к conversation ID, TTL/удаление и совместная
  работа нескольких процессов.
- [ ] **Сделать долговременное хранилище базы знаний.** Документы и версии, фрагменты,
  embeddings/индекс, поиск по смыслу и точные ссылки на товар, раздел и страницу.
- [ ] **Подключить FAQ Workbench к PostgreSQL.** Выполнить миграции, проверить
  уникальности, JSONB, транзакции, повторные `event_id`, lease блокировки и полный цикл
  «вопросы → batch-анализ → черновик → публикация».

### P1 — инструменты и AI-операции

- [ ] **Подключить авторитетный адаптер расчёта корзины/скидок.** AI должен передавать данные
  авторитетному сервису расчёта и только объяснять его ответ, а не считать цены сам.
- [ ] **Подключить авторитетную проверку реквизитов через согласованный валидатор.** Минимизировать
  передаваемые данные и не отправлять их модели без необходимости.
- [ ] **Подключить CRM/оператора к локальной очереди.** Создание обращения, безопасная
  передача контекста, статус/ID подтверждения и понятный ответ пользователю.
- [x] **Подключить админ-агент к операциям подготовки черновиков.** SEO-тексты,
  нормализация и кандидаты-дубли доступны через структурированные API и опираются на
  данные запроса; пока возвращаются вызывающему коду, без сохранения в CMS.
- [ ] **Подключить AI-аналитику к обезличенным событиям чата.** Определить агрегаты,
  сроки хранения и фильтры PII; не передавать модели сырые журналы целиком.
- [ ] **Настроить плановый запуск FAQ batch-пересчёта и его наблюдаемость.** Порог и
  интервал уже поддерживаются API; production scheduler, оповещения об ошибках и
  контроль задержки накопления вопросов ещё не настроены.
- [ ] **Связать AI FAQ API с клиентским интерфейсом.** Передавать событие вопроса с
  повторно используемым `event_id` и получать опубликованные FAQ. UI магазина остаётся
  отдельным проектом; здесь задача только контракта и поведения AI API.
- [x] **Добавить API управления AI-контентом.** Тон, отключаемые темы и FAQ имеют
  валидируемые контракты; постоянное хранение и UI ожидают подключений.

## Внешние зависимости (не задачи AI-сервиса)

AI-реализация потребует тестовых данных каталога, документов и API расчёта/обращений.
Их подготовка и разработка магазина/CMS/CRM/1С/доставки/платежей/«Честного Знака» здесь
не планируются. В этом листе остаются только контракты и адаптеры, через которые AI будет
использовать такие источники.

## Рекомендуемый порядок

1. Параллельно сделать не зависящие от БД AI-черновики SEO/нормализации/дублей и
   подготовить эталонный набор тестов.
2. Согласовать контракты источника каталога и документов, поднять тестовую PostgreSQL
   FAQ Workbench и выполнить реальный интеграционный прогон.
3. Подключить репозитории каталога и знаний, затем принять подбор, сравнение и ответы
   со ссылками на источники.
4. Подключить постоянные сессии, оператора, расчётные инструменты и FAQ batch-процесс.
5. Провести provider/evaluation, privacy/security, нагрузочные и backup/restore проверки
   AI-сервиса. Цель 5–7 секунд подтвердить измерениями до запуска.
