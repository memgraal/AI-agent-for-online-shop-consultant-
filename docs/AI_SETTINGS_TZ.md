# Настройки ИИ-агента по ТЗ

Документ связывает требования к ИИ из `SSS ТЕХНИЧЕСКОЕ ЗАДАНИЕ.docx` с текущим
API и отделяет готовые настройки от функций, которые требуют будущей БД магазина.

## Реализованные пункты

| Пункт ТЗ | Что сделано |
| --- | --- |
| 4. Управление контентом ИИ | Администратор может менять тон, отключённые темы, проверенные FAQ и системные промпты через защищённые API. |
| 4. Лимит токенов и контекста | В настройках хранятся лимиты быстрых/подробных ответов, число сообщений и общий бюджет контекста. |
| 5. Локальный или облачный ИИ | Поддержаны OpenAI, Yandex AI Studio и OpenAI-compatible endpoint, включая локальный Ollama/шлюз. Ключи остаются в окружении. |
| 5. Разграничение доступа | Изменение настроек доступно только через `X-Admin-Key`; секретные ключи не возвращаются и не сохраняются в таблице. |
| 5. Логирование | Изменения настроек фиксируются структурированным событием с номером ревизии без текста промптов и секретов. |
| 8. Документация по шаблонам | Описаны роли промптов и контракты `GET/PUT /api/admin/assistant/settings`. |

## Хранение

При наличии `DATABASE_URL` основной сервис создаёт таблицу `ai_agent_settings`.
В ней одна актуальная строка с ревизией, параметрами модели и JSONB-объектом
`system_prompts`. При старте новые роли промптов добавляются к существующей строке,
но изменённый администратором текст не перезаписывается.

В таблицу не попадают `LLM_API_KEY`, `JEV_LLM_API_KEY`, административные ключи и
другие секреты. База магазина и её будущая база знаний остаются отдельными
источниками данных и не смешиваются с таблицей настроек AI-сервиса.

## API

```text
GET /api/admin/assistant/settings
PUT /api/admin/assistant/settings
```

Роли системных промптов:

- `customer` — клиентский чат;
- `admin` — административный помощник;
- `faq_analysis` — группировка вопросов FAQ;
- `product_seo` — SEO-черновики карточек;
- `attribute_normalization` — нормализация атрибутов.

После изменения настройки загружаются в runtime-кеш, а графы агентов пересоздаются.
Новые промпты применяются без перезапуска процесса.

## Что ещё зависит от БД магазина

- авторитетный каталог, цены, остатки, SKU и совместимость;
- постоянная база знаний с embeddings и ссылками на раздел/страницу;
- внешние источники, которые разрешено подключать только по явному запросу;
- CRM, оператор, 1С, расчёт корзины и проверка существования реквизитов;
- постоянная история клиентских диалогов и аналитика из production-логов.

Пока эти источники не подключены, агент не выдумывает их данные и сообщает о
недоступности проверки.
