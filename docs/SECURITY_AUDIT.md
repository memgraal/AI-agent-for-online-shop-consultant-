# Отчёт по аудиту безопасности

Дата проверки: 2026-10-27.

Проверены сервисы [ai-agent](../) и [faq_workbench](../../faq_workbench/): HTTP-ручки, авторизация, CORS, ограничение запросов, загрузка документов, SQL-запросы, Docker-конфигурация, секреты в Git и Python-зависимости.

## Исправленные проблемы

### Уязвимые зависимости

Проверка установленных пакетов через OSV выявила:

- `certifi` ниже `2026.10.19` — в наборе сертификатов оставался скомпрометированный материал emSign (GHSA-6q48-6c7w-9gw2 / PYSEC-2026-4320).
- `Pillow` ниже `13.0.0` — уязвимости в обработчиках изображений, включая потенциальный отказ в обслуживании.
- `pytest` ниже `9.0.3` — проблема с обработкой временных каталогов. Пакет используется только в тестовом окружении.

Оба окружения обновлены. В [pyproject.toml](../pyproject.toml) и [faq_workbench/pyproject.toml](../../faq_workbench/pyproject.toml) добавлены минимальные безопасные версии, чтобы следующая установка не вернула уязвимые транзитивные пакеты.

## Проверенные контрмеры

- Административные ручки обоих сервисов требуют отдельный заголовок API-ключа и сравнивают ключи через `hmac.compare_digest`.
- Публичный сбор вопросов требует разрешённый `Origin`; список Origin не принимается от клиента.
- На публичных и административных ручках включён rate limit по адресу клиента.
- Заголовок `X-Request-ID` ограничен безопасным набором символов и длиной.
- Ответы и логи не содержат API-ключей; настройки агента в PostgreSQL намеренно не хранят секреты провайдеров.
- SQL использует SQLAlchemy-параметры и статические DDL-выражения, пользовательские строки не интерполируются в SQL.
- Загрузка PDF/DOCX/TXT/MD ограничена размером, количеством страниц и объёмом распаковываемого DOCX-текста; зашифрованные PDF отклоняются.
- Docker-сервисы запускаются от непривилегированного пользователя, с read-only filesystem, `cap_drop: ALL` и `no-new-privileges`.
- Внутренний FAQ-клиент отключает системные прокси (`trust_env=False`), поэтому пользовательский запрос не может перенаправить сервисный вызов через прокси.

## Результаты автоматических проверок

- `pip check` — без конфликтов зависимостей в обоих окружениях.
- AST-поиск опасных вызовов — не обнаружил `eval`, `exec`, `subprocess`, `shell=True` или `pickle`; найденные `json.loads` используются только вместе с Pydantic-валидацией/структурированными данными.
- Проверка отслеживаемых файлов — секретные `.env`, ключи и сертификаты в Git не обнаружены; отслеживается только `.env.example`.

## Ограничения

Сканер `pip-audit`/Bandit не был доступен в окружении, а установленный security-плагин не предоставил вызываемую команду сканирования репозитория. Поэтому CVE-проверка выполнена напрямую через OSV API, а код дополнительно проверен AST-анализом и существующими тестами. При появлении CI-сканера следует запускать его на каждом изменении зависимостей.
